# Radio status icons: EdgeTX 2.12.4 source contract

Research date: 2026-09-19. Scope: the native color-screen Radio Info widget, its link-quality bars, audio indication, and Lua accessibility. Authority is official EdgeTX `v2.12.4`, commit `def35ad324896b45d6607d4778536b1bc5360d20`; the following source links are commit-pinned. Battery normalization and color selection are covered by the [battery comparison](edgetx-2.12.4-battery-icon-comparison.md).

## Link-quality indication

Native Radio Info has five bars. Their enabled thresholds are **>=30, >=40, >=50, >=60, >=80**, respectively. Bar heights follow **5:10:15:21:31**, independently rounded after native display scaling. All enabled bars use theme **PRIMARY2**; disabled bars use **PRIMARY3**. There are no green/amber/red signal bands or user RSSI-warning thresholds in this display. [Construction](https://github.com/EdgeTX/edgetx/blob/def35ad324896b45d6607d4778536b1bc5360d20/radio/src/gui/colorlcd/widgets/radio_info.cpp#L93-L111), [threshold selection](https://github.com/EdgeTX/edgetx/blob/def35ad324896b45d6607d4778536b1bc5360d20/radio/src/gui/colorlcd/widgets/radio_info.cpp#L179-L192).

The native input is `TELEMETRY_RSSI()`, which returns `telemetryData.rssi.value()`. This is the firmware's filtered radio link value, not necessarily a source named `RSSI`, and not uniformly a physical dBm measure across protocols. The filter averages recent observations, while zero or a first observation initializes its history immediately. [Native accessor](https://github.com/EdgeTX/edgetx/blob/def35ad324896b45d6607d4778536b1bc5360d20/radio/src/telemetry/frsky.h#L53-L80), [filter](https://github.com/EdgeTX/edgetx/blob/def35ad324896b45d6607d4778536b1bc5360d20/radio/src/telemetry/telemetry_holders.h#L54-L84).

Lua **`getRSSI()` is the matching public API**. It returns this same value, capped at 99, when telemetry is streaming, and zero otherwise. The cap cannot change any of the five native bar decisions because the highest threshold is 80. Its other return values are configured warning/critical alarms and do not belong in bar selection. On real firmware, link expiry resets the native RSSI filter in the 10 ms telemetry service; Lua zero-on-loss can precede that reset briefly. The reset is disabled under `SIMU`, so simulator stale-state behavior does not establish real-radio parity. [Lua implementation](https://github.com/EdgeTX/edgetx/blob/def35ad324896b45d6607d4778536b1bc5360d20/radio/src/lua/api_general.cpp#L2092-L2114), [expiry](https://github.com/EdgeTX/edgetx/blob/def35ad324896b45d6607d4778536b1bc5360d20/radio/src/telemetry/telemetry.cpp#L391-L415).

CRSF, including ELRS, assigns **RX link quality** to that radio filter. Therefore a raw `RQly` telemetry sensor can differ during transitions because it does not necessarily carry the same filter; `1RSS` is a different measurement. The same `getRSSI()` path should be used for OMP carried over CRSF. Native matching must not substitute a synthetic 100 merely because a receiver or pack telemetry source is present. [CRSF assignment](https://github.com/EdgeTX/edgetx/blob/def35ad324896b45d6607d4778536b1bc5360d20/radio/src/telemetry/crossfire.cpp#L300-L329).

`getSourceValue("RSSI")` is not an alias for that native accessor: Lua's fixed source list contains transmitter voltage and clock, but no fixed RSSI source; names also resolve model telemetry sensors. Sensor values include separate current/fresh metadata and may retain the last value. Prefer the actual `getRSSI()` result, including its valid zero, over named telemetry fallbacks. Any missing-API fallback must be documented as degraded rather than exact. [Fixed fields](https://github.com/EdgeTX/edgetx/blob/def35ad324896b45d6607d4778536b1bc5360d20/radio/src/lua/api_general.cpp#L369-L419), [source API contract](https://github.com/EdgeTX/edgetx/blob/def35ad324896b45d6607d4778536b1bc5360d20/radio/src/lua/api_general.cpp#L727-L772).

## Audio indication and a firmware API limitation

The native audio indicator selects five states from the **current requested speaker volume**:

| State | Native condition |
|---|---|
| Muted | `requiredSpeakerVolume == 0` **or** radio `beepMode == e_mode_quiet` |
| 1 | Nonmuted volume below 7 |
| 2 | Volume 7–12 |
| 3 | Volume 13–18 |
| 4 | Volume >=19 |

The glyph uses PRIMARY2; the background audio scale uses PRIMARY3. Its battery is horizontal underneath. [Audio construction](https://github.com/EdgeTX/edgetx/blob/def35ad324896b45d6607d4778536b1bc5360d20/radio/src/gui/colorlcd/widgets/radio_info.cpp#L55-L73), [audio selection](https://github.com/EdgeTX/edgetx/blob/def35ad324896b45d6607d4778536b1bc5360d20/radio/src/gui/colorlcd/widgets/radio_info.cpp#L137-L152).

The live requested volume can come from the radio's default setting or active Volume special functions. The special-function mapping includes a dead zone and integer scaling, rather than a simple percent-to-quartile conversion. [Default volume](https://github.com/EdgeTX/edgetx/blob/def35ad324896b45d6607d4778536b1bc5360d20/radio/src/mixer.cpp#L1213-L1218), [special-function override](https://github.com/EdgeTX/edgetx/blob/def35ad324896b45d6607d4778536b1bc5360d20/radio/src/functions.cpp#L319-L331).

**Stock EdgeTX 2.12.4 does not expose live requested speaker volume or radio beep mode through its public Lua API.** `getGeneralSettings()` exposes battery warning/range, units, language, voice language, and global timer only. Searching the Lua API implementation finds audio-playback volume overrides and the `FUNC_VOLUME` constant, but no volume-state getter. `model.getCustomFunction()` reads model special-function configuration only; it cannot establish the radio default, global functions, or quiet mode. A configured pot, saved radio YAML, or model function alone therefore cannot reproduce the native indicator reliably. [General settings implementation](https://github.com/EdgeTX/edgetx/blob/def35ad324896b45d6607d4778536b1bc5360d20/radio/src/lua/api_general.cpp#L1739-L1763), [model function getter](https://github.com/EdgeTX/edgetx/blob/def35ad324896b45d6607d4778536b1bc5360d20/radio/src/lua/api_model.cpp#L1386-L1429), [Lua API sources](https://github.com/EdgeTX/edgetx/tree/def35ad324896b45d6607d4778536b1bc5360d20/radio/src/lua).

A truthful dashboard must distinguish unavailable audio state from mute. Exact automatic volume parity requires a verified additional firmware API or leaving the actual native status widget visible. Do not silently invent a live API, infer volume from arbitrary hardware controls, or show a fixed volume level as if it were measured.

## Drawing and integration implications

Native audio artwork is supplied as five SVG masks plus a scale mask under `radio/src/bitmaps/img-src/volume`. These are built into native icon resources, with GPLv2 provenance in the firmware. The Lua LVGL library exposes rectangles, triangles, lines, circles, arcs and file-backed images, but no native Radio Info widget or built-in icon constructor. A simplified speaker/arc drawing is possible without adding file dependencies; a native asset reproduction needs appropriate attribution and distributable assets. [Official artwork](https://github.com/EdgeTX/edgetx/tree/def35ad324896b45d6607d4778536b1bc5360d20/radio/src/bitmaps/img-src/volume), [Lua constructors](https://github.com/EdgeTX/edgetx/blob/def35ad324896b45d6607d4778536b1bc5360d20/radio/src/lua/api_colorlcd_lvgl.cpp#L440-L477), [file-backed image](https://github.com/EdgeTX/edgetx/blob/def35ad324896b45d6607d4778536b1bc5360d20/radio/src/lua/lua_lvgl_widget.cpp#L2021-L2026).

The user-selected implementation changes only the link display: one shared native-input/bar calculation serves KSE4 and KSE5, separate from aircraft connection/RF safety decisions. Preserve the existing vertical transmitter battery unchanged, and defer the volume indicator until a verified firmware API can expose live volume and quiet mode. Five ascending bars retain the native thresholds and height proportions, adapted to the smaller headers with minimum three-pixel bars and two-pixel gaps. Enabled bars use dashboard text color; disabled bars use dashboard line/border color. This preserves the native monochrome enabled/disabled distinction and each KSE theme, without claiming exact native theme RGB matching. Test every threshold boundary, authoritative zero with stale named sensors, protocol independence, and cross-variant output. Desktop source review and mocks do not establish physical-radio readability, timing, memory, or RF results.
