# Dashboard compatibility contracts

These are the current preservation rules for the shared engine and both generated dashboards. Read the relevant contract before changing behavior. The [source guide](../src/README.md) owns assembly and test entry points; [runtime resources](runtime-resources.md) owns resource limits and measurement caveats; [transmitter validation](transmitter-validation.md) records the outstanding hardware gates.

Source evidence is tied to the cited commits, not every later firmware release. The fixture compiler uses EdgeTX v2.12.1 `1511b3f29152f18c704f1f89b3608e0f71317de9`; RF fixtures use Rotorflight Lua 2.3 `aaacfe68407c09d49a26c5aa326c00119b378bb0`. Rotorflight firmware `release/4.6.0` at `118e9120260bb33f46df4f92052fb0e9fd4e9ebc` is the 2.3 firmware series; its tag numbering differs from the Lua package. Later API checks identify their own versions below. Recheck the affected implementation and upstream version when extending a contract.

## RF admission policy

The user selected **unmodified RF Tool with confirmed-disarm admission for all new KSE-owned MSP requests**. Every request, including profile writes and continuation stages, requires valid, current ARM bit 0 disarmed with bounded recent-update evidence, a live link, a ready provider and no armed host contradiction. `Gov` and `Hspd` are neither sampled nor restricted for MSP admission: rotation does not block requests when disarm is confirmed. There is no extra 40-tick (0.4-second) settle gate. Preserve the existing 150-tick FC-count post-disarm settle and unrelated connection/rate intervals.

Invalidate stale callbacks and remove safely identifiable pending owned entries when confirmed disarm is lost. Preserve sensor identity checks, staged verification/save, timeouts, active upstream transactions, foreign queue work, and official RF Tool initialization, recovery and page activity.

An already-active KSE request may continue fragments/retries indefinitely and may still affect the FC after KSE invalidates its operation. That is an accepted upstream limitation. Admission control provides no zero-wire-traffic or per-send cancellation guarantee and establishes no measured latency improvement. See [RF integration](rf-integration.md) for provider servicing, continuation stages and upstream receive limitations.

Normal telemetry, Smart Fuel, flight instruments, alerts and local counters continue; governor and headspeed remain display/alert inputs. Clear the pre-arm blocker banner whenever disarm cannot be confirmed; resume fresh diagnostics, configuration and post-flight FC count reads after confirmation returns, subject to their existing intervals.

## ARM update timing contract

Use one observed-update window for MSP admission, FC-count settling and the footer: read the actual `ARM` value and `isCurrent` on every check, resolve its sensor ID every time, and require a valid integer byte. An observed `isFresh == true` records a timestamp on the owning widget. That evidence remains eligible through 400 ticks (four seconds) only while the source stays current and its identity is unchanged. Never return a cached ARM value. A current armed value or armed host contradiction still denies admission immediately.

Clear the timestamp on missing/invalid/noncurrent data, source-ID change, backwards time, expiry, link/provider unavailability, model/provider/queue/host/Auto-aircraft context change, or reset. Startup or recovery without an observed update waits for the next fresh pulse. Valid armed samples can refresh the timestamp for a stable footer; they never authorize a request. Context, byte validation, callback epochs and pending-only cancellation remain mandatory.

Rotorflight 2.3 firmware's [ARM intervals](https://github.com/rotorflight/rotorflight-firmware/blob/118e9120260bb33f46df4f92052fb0e9fd4e9ebc/src/main/telemetry/crsf.c#L816) are 200 ms changed and 3,000 ms unchanged; the [scheduler selects between them](https://github.com/rotorflight/rotorflight-firmware/blob/118e9120260bb33f46df4f92052fb0e9fd4e9ebc/src/main/telemetry/telemetry.c#L251-L266), with up to 99 ms added to the slow interval during initialization. EdgeTX's [fresh pulse](https://github.com/EdgeTX/edgetx/blob/1511b3f29152f18c704f1f89b3608e0f71317de9/radio/src/telemetry/telemetry_sensors.h#L111-L124) lasts roughly 160–320 ms, whereas an individually silent sensor can remain current for about [20 seconds](https://github.com/EdgeTX/edgetx/blob/1511b3f29152f18c704f1f89b3608e0f71317de9/radio/src/telemetry/telemetry_sensors.h#L25-L28). Requiring the pulse continuously caused false missing-ARM warnings and repeatedly reset the FC counter's 150-tick settle. The four-second observation window covers ordinary unchanged updates without adopting the much longer current-only timeout or adding telemetry traffic.

The window is a bound on the last **observed fresh flag**, not an exact packet timestamp: firmware can already consider that packet up to roughly 320 ms old. Delayed/lost armed telemetry can delay detecting an actual arm; existing admission-only and upstream-retry limitations still apply. A callback pause that misses updates may require the next fresh pulse after resuming. Motor-stop alert rules remain separate. OMP identification follows its [voltage-only connection contract](omp-auto-identification-feasibility.md#omp-auto-implementation-contract).

Regression contracts cover three-second update pulses, armed/disarmed footer stability, initial and post-flight FC reads with the original 150-tick settle, expiry while still current, invalid fresh bytes, clock rollback, identity/reset/link recovery, armed readings between pulses, and expired-operation callbacks. Hardware validation must still confirm normal reception and intentional sensor/link loss on the radio.

## Transmitter-battery icon alignment

The transmitter-battery icon follows the separate [EdgeTX 2.12.4 alignment contract](edgetx-2.12.4-battery-icon-comparison.md#implementation-contract): shared radio range, native integer fill rounding and color bands for the physical screen, native default RGB colors, and hidden fill at zero. The TX chemistry/fallback setting is removed with the authorized fresh settings setup. Missing or invalid native battery ranges leave the fill empty; no alternate chemistry range is substituted. [Behavior](../tests/behavior/README.md) and [render](../tests/render/README.md) fixtures cover this boundary; physical-radio appearance and timing remain separate validation.

## Native signal display and deferred volume

Follow the [EdgeTX 2.12.4 status-icon contract](edgetx-2.12.4-status-icons.md): the display uses native filtered `getRSSI()` and five thresholds (30/40/50/60/80) without changing the named-sensor link evidence used by alerts and RF admission. Five monochrome bars retain native height proportions with dashboard theme colors and readable pixel minima. The user selected retaining the vertical battery and deferring volume until a supported firmware API exposes live volume and quiet mode. Source-backed limitations and physical-radio checks remain separate from mocked behavior/render tests.

## Saved-model ownership handoff

EdgeTX retains widget Lua state while replacing the widgets for a newly selected model. A global KSE owner can therefore outlive its actual screen. Use the saved model filename and an observed model generation captured at widget creation to distinguish this retired owner from a duplicate on the same model. Retire pending owned work on the first observed known filename change, including observations from old callbacks; preserve active RF Tool transactions, foreign queue work and shared dirty counts. Only a current-model foreground refresh may replace the owner, skipping the 500-tick lease when a known model-session change proves the old widget obsolete. Same-model recreation and missing filename evidence keep the lease fallback. Unknown filename samples do not reset the generation. Callbacks from a retired observed model session cannot renew the lease, admit MSP, clear the replacement screen or revive after an observed A→B→A sequence.

Source evidence: EdgeTX v2.12.4 `def35ad324896b45d6607d4778536b1bc5360d20` [changes the selected filename and recreates screens](https://github.com/EdgeTX/edgetx/blob/def35ad324896b45d6607d4778536b1bc5360d20/radio/src/gui/colorlcd/model/model_select.cpp#L377-L401); [`model.getInfo()` exposes that filename separately from the display name](https://github.com/EdgeTX/edgetx/blob/def35ad324896b45d6607d4778536b1bc5360d20/radio/src/lua/api_model.cpp#L45-L82). The [widget destructor](https://github.com/EdgeTX/edgetx/blob/def35ad324896b45d6607d4778536b1bc5360d20/radio/src/lua/lua_widget.cpp#L230-L272) has no Lua deletion callback. Filename is not a unique load identifier: reloading the same file, or an intervening model change never observed by KSE, still needs the fallback. [Ownership fixtures](../tests/ownership/README.md) exercise both variants and cross-variant handoff; actual transmitter timing remains a separate check.

## Auto helicopter type integration contract

Auto Elec/Nitro is the third Helicopter type menu entry, retaining saved ID 4. Electric and Nitro remain IDs 1 and 2, with Electric the default. The shared engine confirms a nonempty connected FC name for 30 ticks, infers Nitro from a case-insensitive trailing `N` or `Nitro`, and otherwise selects Electric. It never infers OMP. The confirmed name supplies display/image lookup and the existing normalized local-count key; changing it does not migrate stored history.

RF Tool already obtains the name through [its initialization read](https://github.com/rotorflight/rotorflight-lua-scripts/blob/aaacfe68407c09d49a26c5aa326c00119b378bb0/src/SCRIPTS/RF2/background_init.lua#L130-L156), independently of the optional transmitter rename. KSE adds no name polling. The [upstream disconnected transition](https://github.com/rotorflight/rotorflight-lua-scripts/blob/aaacfe68407c09d49a26c5aa326c00119b378bb0/src/WIDGETS/RfTool/app.lua#L81-L89) clears that published name. Evidence remains tied to the RF Tool version identified above.

Unresolved Auto pauses type-dependent alerts, profile operations and local/FC counting while ordinary telemetry continues. Diagnostics remain subject to the same confirmed-disarm admission policy. Preserve last confirmed identity during disconnect and warning latches through a brief RSSI dropout; observed RF reconnection, name/provider/queue/host replacement requires new confirmation and a new session. Hidden callbacks may resolve identity but must defer rebuilding the UI until foreground refresh. Duplicate inactive widgets must not reset the owner's Auto state or dirty count storage.

Check current FC identity at callback admission as well as at refresh, including same-type name changes with transmitter naming disabled. Invalidate old callbacks and remove pending owned work before embedded service; preserve active transactions and foreign work. Do not restore the feature branch's old `queue.clear()` cancellation: [upstream clear](https://github.com/rotorflight/rotorflight-lua-scripts/blob/aaacfe68407c09d49a26c5aa326c00119b378bb0/src/SCRIPTS/RF2/MSP/mspQueue.lua#L139-L145) resets the active transport and violates the selected boundary.

Acceptance is covered by [Auto lifecycle contracts](../tests/auto_type/README.md), [MSP admission contracts](../tests/msp_admission/README.md) and the existing ownership, rendering, storage and compiler gates. Validate 29/30-tick confirmation, stale callbacks between profile stages, same-name provider replacement, manual/Auto transitions, strict fractional-option rejection, FC-name counts and all three display sizes. Real-radio name timing, memory, UI, SD and RF behavior remain in [transmitter validation](transmitter-validation.md).

## Nitro fuel reminder contract

The shared telemetry service reads Timer 1 at the existing 10 Hz cadence for both counter choices. Manual Nitro or confirmed Auto Nitro queues one `BatterySounds/fuel.wav` announcement and one normal-priority haptic at the configured elapsed duration. The Nitro page uses a native numeric editor displaying `Off` or `00:15`–`30:00` in 15-second steps. Its internal saved index is 1–121, with index 1 for Off and default index 25 for `06:00`. Accept only finite integer indices in that range; convert to seconds with `(index - 1) * 15`. Off and invalid indices disable both sound and haptic. Fresh setup defaults to six minutes; saved records require this field. Electric/OMP remain silent; simulation cannot emit the reminder. Battery Voice controls battery warnings only. No timer configuration, telemetry sensor or MSP request is added.

Keep eligibility independent of RF/type/battery-alert resets: an observed elapsed time below the configured threshold rearms it. Changing the fuel duration clears eligibility; the new threshold must first be observed ahead of the timer, so enabling/lowering an already-expired reminder cannot backfill an alert. An instance first loaded with an already-expired timer stays silent until that reset. Theme/counter/type edits, disarming and reconnects cannot replay a completed reminder. If confirmation/link is unavailable at the threshold, retain the pending reminder until Nitro is confirmed and the link returns; a confirmed Electric/OMP run retires it without alerting. This follows the user's timer, including any spool-up it counts; the widget does not infer airborne time or fuel quantity.

Configuration is owned entirely by the [fullscreen settings menu](settings-menu.md). Keep the native descriptor explicitly empty and start upgrades from defaults; no native option-slot migration, legacy text conversion or old-firmware fixed-duration path remains. The numeric editor stores only valid quarter-minute steps and avoids constructing a 121-entry choice popup. EdgeTX 2.12.4 provides the reviewed [number editor and display callback](https://github.com/EdgeTX/edgetx/blob/def35ad324896b45d6607d4778536b1bc5360d20/radio/src/lua/lua_lvgl_widget.cpp). The menu's firmware/API gate applies to this control too.

EdgeTX v2.12.4 `def35ad324896b45d6607d4778536b1bc5360d20` exposes Timer 1 as [index 0 with raw `start` and `value` seconds](https://github.com/EdgeTX/edgetx/blob/def35ad324896b45d6607d4778536b1bc5360d20/radio/src/lua/api_model.cpp#L284-L327), and [reset restores the start value](https://github.com/EdgeTX/edgetx/blob/def35ad324896b45d6607d4778536b1bc5360d20/radio/src/timers.cpp#L36-L41). Reuse elapsed `start - value` for countdown and `value` for count-up. The API has no reset generation: a reset wholly during suspended widget execution cannot be detected. [Ordinary hidden widgets receive background callbacks](https://github.com/EdgeTX/edgetx/blob/def35ad324896b45d6607d4778536b1bc5360d20/radio/src/gui/colorlcd/mainview/widgets_container.cpp#L86-L98); [standalone Lua tools suspend widget refresh](https://github.com/EdgeTX/edgetx/blob/def35ad324896b45d6607d4778536b1bc5360d20/radio/src/gui/colorlcd/standalone_lua.cpp#L126-L136).

Use the existing file-availability helper with a short mono PCM16/32 kHz clip and two queued fallback tones if unavailable. `playFile`'s optional second argument is [volume, not priority](https://github.com/EdgeTX/edgetx/blob/def35ad324896b45d6607d4778536b1bc5360d20/radio/src/lua/api_general.cpp#L1455-L1503). Queue `playHaptic(15, 0, 0)`: [`PLAY_NOW` clears existing haptic feedback](https://github.com/EdgeTX/edgetx/blob/def35ad324896b45d6607d4778536b1bc5360d20/radio/src/haptic.cpp#L71-L92). These timer/audio APIs were also checked against pinned EdgeTX 2.12.1. Successful Lua calls do not prove native playback or queue delivery.

Validate with the [Auto lifecycle fixtures](../tests/auto_type/README.md), existing behavior/MSP/ownership/storage/render gates, and every-prototype compiler checks. Measure resource deltas and keep real-radio speech, haptic strength, scheduling and memory validation separate.

## OMP automatic identity contract

The separate [OMP automatic identity contract](omp-auto-identification-feasibility.md#omp-auto-implementation-contract) supplies all OMPHOBBY functionality through the fourth menu entry, retaining saved ID 5. The former manual OMP ID 3 now resolves to this same automatic behavior; no name-based cell-count fallback remains. Rotorflight Auto keeps its own name provider. [OMP lifecycle contracts](../tests/omp_auto/README.md) cover this path; its voltage-based identity selection remains independent of the ARM-only MSP admission policy.

## Flight-count arming-status contract

Both footer renderers consume the shared engine's display status. A live radio link and ready current RF provider are required. `ARMED` or `DISARMED` requires agreement between the current host state and valid, current ARM bit 0 with bounded recent-update evidence; uncertain or contradictory ARM evidence leaves the neutral `CONNECTED` label. Missing or initializing host state and link/provider loss clear the label. OMP omits RF status. This display calculation does not invoke admission decisions or request MSP data; status changes invalidate retained text even between telemetry samples and across background/foreground transitions.

RF Tool [updates armed/disarmed state on ARM changes](https://github.com/rotorflight/rotorflight-lua-scripts/blob/aaacfe68407c09d49a26c5aa326c00119b378bb0/src/WIDGETS/RfTool/app.lua#L66-L89) and [retains its state through short RSSI outages](https://github.com/rotorflight/rotorflight-lua-scripts/blob/aaacfe68407c09d49a26c5aa326c00119b378bb0/src/SCRIPTS/RF2/background.lua#L31-L36). The footer therefore checks live link and the [EdgeTX current/fresh source flags](https://github.com/EdgeTX/edgetx/blob/1511b3f29152f18c704f1f89b3608e0f71317de9/radio/src/lua/api_general.cpp#L748-L768) instead of presenting cached RF state as current. [Auto/footer lifecycle contracts](../tests/auto_type/README.md) cover both variants, counter choices and all three display sizes. Physical rendering and radio timing remain part of [transmitter validation](transmitter-validation.md).

## EdgeTX / Rotorflight rules the implementation must preserve

1. **Use supported widget callbacks and EdgeTX APIs.** Keep `useLvgl=true`, retain LVGL objects, rebuild on actual layout/theme changes, and avoid LCD drawing from background. Do not import desktop Lua file methods, `os`, package-loader assumptions, or radio-incompatible compiled bytecode. Check both parser locals and runtime callback limits.
2. **Keep the shared settings contract.** Both dashboards use the same functional schema/defaults and separate theme entries; theme indices intentionally map to different palettes. Keep `options={}` and ignore native payloads. This menu transition starts upgrades from defaults; preserve subsequent version-2 menu saves unless another reset is explicitly authorized.
3. **Keep Rotorflight sensor semantics.** `Vcel` is a scalar average-cell voltage in the RF telemetry contract; it is not an EdgeTX `Cels` table. Preserve average-cell voltage rather than substituting weakest-cell voltage. Keep `Curr`, ARM bit 0, and one-based BAT#/PID#/RTE# conventions. [RF2 sensor definitions](https://github.com/rotorflight/rotorflight-lua-scripts/blob/aaacfe68407c09d49a26c5aa326c00119b378bb0/src/SCRIPTS/RF2/rf2tlm_sensors.lua).
4. **Preserve Smart Fuel authority.** Valid Rotorflight `Bat%` is the FC charge estimate; do not replace it with voltage-only percentage or add smoothing to the FC estimate as a performance “optimization.” Keep missing/zero/USB-power distinctions and reserve behavior. [Rotorflight battery charge selector](https://github.com/rotorflight/rotorflight-firmware/blob/118e9120260bb33f46df4f92052fb0e9fd4e9ebc/src/main/sensors/battery.c#L193-L211).
5. **Keep MSP layouts versioned.** Battery profile read/write use 175/176 with zero-based wire indices; save is 250. Verify battery-config/state offsets against the supported firmware. Do not guess that a truncated modern response is a valid legacy packet solely from its length. Flight stats uses read command 14; never send setter 15 for this display. Use the upstream [flight-stat API decoder](https://github.com/rotorflight/rotorflight-lua-scripts/blob/aaacfe68407c09d49a26c5aa326c00119b378bb0/src/SCRIPTS/RF2/MSP/mspFlightStats.lua) and retain API checks and disabled-stat handling.
6. **Account for callback suspension outside normal screens.** EdgeTX ordinarily services widgets on other screens; a blanket claim that another screen gets no callbacks is incorrect. Standalone Lua tools explicitly disable widget refresh while active, so widget-only warnings are not continuously guaranteed in that state. Do not attempt to solve this by automatically adding conflicting `rf2bg` functions. See [standalone tool lifecycle](https://github.com/EdgeTX/edgetx/blob/1511b3f29152f18c704f1f89b3608e0f71317de9/radio/src/gui/colorlcd/standalone_lua.cpp#L136) and [main-view widget service](https://github.com/EdgeTX/edgetx/blob/1511b3f29152f18c704f1f89b3608e0f71317de9/radio/src/gui/colorlcd/view_main.cpp#L408-L421). Ordinary `lvgl.dialog` suspension was **not established** by the pinned source review; test that behavior before depending on it.
