# EdgeTX feasibility: on-radio setup and diagnostics

Research date: 2026-09-23. See the [implementation plan](setup-diagnostics-panel-plan.md) for scope, entrypoint placement and sequencing. This is a source-backed planning note, not an implementation or transmitter validation result. The proposed panel should explain KSE's existing observations, remain usable when disconnected or ARM is missing, and add no MSP requests.

## Versions examined

Nightly builds are a separate prerelease track. The 2.11 series is still relevant to older radios; its newer 2.11.7 release was visible, but its implementation was not audited here.

## Entrypoint: fullscreen first

**Use EdgeTX's existing Full screen route, then a visible KSE `Info` button.** A one-tap interactive button on an ordinary, non-fullscreen widget is not supported by these implementations.

Terminology: the [EdgeTX 2.11 change summary](https://manual.edgetx.org/v2.11/summary_of_changes) calls interactive fullscreen widget operation **App mode**. This is distinct from the saved **App mode layout** setting: entering fullscreen changes the widget’s interaction state, not the configured layout. The native fullscreen transition and exit paths are cited below.

The restrictions are in the implementation, even though constructing a button eventually uses a normal native button:

- `lvgl.button`, `lvgl.dialog`, and `lvgl.page` are registered with `fullscreenOnly=true`. Their wrapper returns `nil` outside fullscreen. `lvgl.build` also skips interactive control types outside fullscreen. See [2.12.4 registrations](https://github.com/EdgeTX/edgetx/blob/def35ad324896b45d6607d4778536b1bc5360d20/radio/src/lua/api_colorlcd_lvgl.cpp#L462-L481), [wrapper](https://github.com/EdgeTX/edgetx/blob/def35ad324896b45d6607d4778536b1bc5360d20/radio/src/lua/api_colorlcd_lvgl.cpp#L318-L366), and [builder gate](https://github.com/EdgeTX/edgetx/blob/def35ad324896b45d6607d4778536b1bc5360d20/radio/src/lua/api_colorlcd_lvgl.cpp#L186-L196). The same gates exist in [2.11.5](https://github.com/EdgeTX/edgetx/blob/2273bda7b9e650c96a39a6e7f1316b6ef8415dad/radio/src/lua/api_colorlcd_lvgl.cpp#L454-L473) and [2.12.1](https://github.com/EdgeTX/edgetx/blob/1511b3f29152f18c704f1f89b3608e0f71317de9/radio/src/lua/api_colorlcd_lvgl.cpp#L462-L481).
- Raw `refresh(widget, event, touch)` receives `nil` event/touch outside fullscreen. A manually drawn hotspot cannot bypass this restriction. [2.12.4 event delivery](https://github.com/EdgeTX/edgetx/blob/def35ad324896b45d6607d4778536b1bc5360d20/radio/src/lua/lua_widget.cpp#L504-L522).
- The native widget menu contains Full screen and Widget settings. It is built by C++, with no custom Lua menu callback in this path. `lvgl.menu` creates a separate popup; it does not append an item to that native context menu. [Native menu](https://github.com/EdgeTX/edgetx/blob/def35ad324896b45d6607d4778536b1bc5360d20/radio/src/gui/colorlcd/mainview/widget.cpp#L173-L192), [Lua menu builder](https://github.com/EdgeTX/edgetx/blob/def35ad324896b45d6607d4778536b1bc5360d20/radio/src/lua/lua_lvgl_widget.cpp#L2855-L2872).
- Lua exposes `lvgl.isFullScreen()` and `lvgl.exitFullScreen()`, but no corresponding enter-fullscreen function in this API table. Do not promise that tapping an ordinary dashboard label can request fullscreen. [Implemented functions](https://github.com/EdgeTX/edgetx/blob/def35ad324896b45d6607d4778536b1bc5360d20/radio/src/lua/api_colorlcd_lvgl.cpp#L402-L417), [registration table](https://github.com/EdgeTX/edgetx/blob/def35ad324896b45d6607d4778536b1bc5360d20/radio/src/lua/api_colorlcd_lvgl.cpp#L442-L493).

Source-backed user routes:

| Input | Route |
| --- | --- |
| Touch, ordinary widget | Long-press the KSE widget → Full screen → tap Info. |
| Hardware keys/wheel, ordinary layout | Long-press ENTER to enter widget selection → select KSE with the wheel → ENTER → Full screen → focus Info with the wheel → ENTER. |
| EdgeTX app-mode layout | Long ENTER enters the sole widget's fullscreen mode directly; then Info. Do not require users to change their existing layout to app mode. |
| Already fullscreen | Tap or focus Info directly. |

The widget's [long press opens the menu](https://github.com/EdgeTX/edgetx/blob/def35ad324896b45d6607d4778536b1bc5360d20/radio/src/gui/colorlcd/mainview/widget.cpp#L260-L267); [main-view long press and selection](https://github.com/EdgeTX/edgetx/blob/def35ad324896b45d6607d4778536b1bc5360d20/radio/src/gui/colorlcd/mainview/view_main.cpp#L289-L340) establish the hardware route; the widget's [press handler](https://github.com/EdgeTX/edgetx/blob/def35ad324896b45d6607d4778536b1bc5360d20/radio/src/gui/colorlcd/mainview/widget.cpp#L165-L170) opens the menu when selected. Physical key naming and focus behavior need transmitter verification.

Use a real native Info button in fullscreen, with a compact noninteractive `Full screen → Info` hint only if discoverability requires it outside fullscreen. Opening diagnostics must not depend on an ARM/disarm check, a radio link, RF Tool initialization, or a successful profile lookup: those are exactly the conditions users need explained. Opening the panel itself is a local read-only UI action.

## Rendering and navigation

Prefer **an in-widget diagnostics view** to a modal dialog or standalone Lua tool. Keep the same KSE widget and its service callbacks active. A shared implementation can use two retained `lvgl.box` roots: the existing dashboard and a diagnostics root created lazily on first fullscreen access. Hide one and show the other; keep images in the dashboard root. Build one bounded diagnostics hierarchy, change label contents or a small details region on page changes, and rebuild only on real geometry/theme/ownership changes.

This strategy uses verified operations:

- `lvgl.hide(root)`, `lvgl.show(root)`, and `lvgl.clear(root)` dispatch to the retained object. Explicit-parent creation is supported. [Object operations](https://github.com/EdgeTX/edgetx/blob/def35ad324896b45d6607d4778536b1bc5360d20/radio/src/lua/api_colorlcd_lvgl.cpp#L125-L155), [explicit parent](https://github.com/EdgeTX/edgetx/blob/def35ad324896b45d6607d4778536b1bc5360d20/radio/src/lua/api_colorlcd_lvgl.cpp#L336-L366).
- Hiding a native window toggles its hidden flag; it does not delete its children. The Lua retained-property traversal skips hidden subtrees. Engine telemetry/service work must therefore stay in refresh/background, not in a hidden label getter. [Window visibility](https://github.com/EdgeTX/edgetx/blob/def35ad324896b45d6607d4778536b1bc5360d20/radio/src/gui/colorlcd/libui/window.cpp#L418-L442), [retained traversal](https://github.com/EdgeTX/edgetx/blob/def35ad324896b45d6607d4778536b1bc5360d20/radio/src/lua/lua_lvgl_widget.cpp#L665-L707).
- A Lua text button constructs a native `TextButton`. Its class participates in the native focus group; normal native click/ENTER calls the press handler. [Lua button](https://github.com/EdgeTX/edgetx/blob/def35ad324896b45d6607d4778536b1bc5360d20/radio/src/lua/lua_lvgl_widget.cpp#L2152-L2170), [native button class and click](https://github.com/EdgeTX/edgetx/blob/def35ad324896b45d6607d4778536b1bc5360d20/radio/src/gui/colorlcd/libui/button.cpp#L31-L107).
- KSE is an LVGL widget: EdgeTX explicitly disables the non-LVGL fullscreen rotary editing mode for it. Do not design raw `EVT_ROTARY_LEFT/RIGHT` as if delivery were automatic; use native focusable buttons. [LVGL rotary distinction](https://github.com/EdgeTX/edgetx/blob/def35ad324896b45d6607d4778536b1bc5360d20/radio/src/lua/lua_widget.h#L135-L141).

Use explicit Back, Previous, and Next controls with a visible page indicator, rather than touch-only swipe navigation. Give short EXIT a local Back behavior where it is delivered. Long EXIT is handled natively to leave fullscreen, independently of KSE's next callback; the next foreground refresh must notice fullscreen loss, close local diagnostics state, and restore the dashboard. A separate native button may call `lvgl.exitFullScreen()` for touch-only exit. [Native long EXIT](https://github.com/EdgeTX/edgetx/blob/def35ad324896b45d6607d4778536b1bc5360d20/radio/src/gui/colorlcd/mainview/widget.cpp#L194-L201), [fullscreen transitions](https://github.com/EdgeTX/edgetx/blob/def35ad324896b45d6607d4778536b1bc5360d20/radio/src/gui/colorlcd/mainview/widget.cpp#L208-L258).

Use KSE's 800×480 design coordinates, but page content according to usable height. The 480×272 view should show fewer rows with the same readable labels and touch targets; 480×320 can show an extra row; 800×480 can show more explanation. Do not shrink a desktop-sized diagnostic table until it fits. If any later feature uses `lvgl.dialog`, account for the native header: its body is the requested height minus `UI_ELEMENT_HEIGHT`, which is 32 pixels on both 480-wide displays and 44 at 800×480. [Dialog body](https://github.com/EdgeTX/edgetx/blob/def35ad324896b45d6607d4778536b1bc5360d20/radio/src/lua/lua_lvgl_widget.cpp#L2649-L2705), [theme scaling](https://github.com/EdgeTX/edgetx/blob/def35ad324896b45d6607d4778536b1bc5360d20/radio/src/gui/colorlcd/libui/etx_lv_theme.h#L58-L72), [element height](https://github.com/EdgeTX/edgetx/blob/def35ad324896b45d6607d4778536b1bc5360d20/radio/src/gui/colorlcd/libui/etx_lv_theme.h#L282).

`lvgl.page` itself is a child `WidgetPage` derived from `NavWindow`; that constructor only sets an opaque flag, and this Lua page does not call `pushLayer()`. It is not the same implementation as a native model `Page`, which does push a layer. It is therefore not rejected as inherently modal; the box approach avoids unnecessary header and event behavior. [WidgetPage](https://github.com/EdgeTX/edgetx/blob/def35ad324896b45d6607d4778536b1bc5360d20/radio/src/lua/lua_lvgl_widget.cpp#L2416-L2520), [NavWindow](https://github.com/EdgeTX/edgetx/blob/def35ad324896b45d6607d4778536b1bc5360d20/radio/src/gui/colorlcd/libui/window.cpp#L534-L539), [native Page layer](https://github.com/EdgeTX/edgetx/blob/def35ad324896b45d6607d4778536b1bc5360d20/radio/src/gui/colorlcd/libui/page.cpp#L73-L105).

## Lifecycle differs between supported releases

**2.12.1 and 2.12.4:** main-window service calls `ViewMain::refreshWidgets()` before dispatching events to the top opaque layer. Widgets on another screen receive background callbacks; fullscreen widgets take the foreground route. An ordinary dialog does not itself switch off widget refresh in this path. [Main-window service](https://github.com/EdgeTX/edgetx/blob/def35ad324896b45d6607d4778536b1bc5360d20/radio/src/gui/colorlcd/libui/mainwindow.cpp#L54-L70), [foreground/background dispatch](https://github.com/EdgeTX/edgetx/blob/def35ad324896b45d6607d4778536b1bc5360d20/radio/src/gui/colorlcd/mainview/widgets_container.cpp#L86-L98), [2.12.1 equivalent](https://github.com/EdgeTX/edgetx/blob/1511b3f29152f18c704f1f89b3608e0f71317de9/radio/src/gui/colorlcd/libui/mainwindow.cpp#L57-L73).

**2.11.5:** main-window service dispatches `checkEvents()` only through the first opaque layer, and Lua widget refresh/background servicing is inside the widget's `checkEvents()`. A modal dialog pushes its own opaque layer. Together these source paths predict that a modal diagnostics dialog can suspend underlying KSE widget service on this baseline. Treat this as a source-derived conclusion requiring a radio reproduction, and avoid making it the baseline UI route. [Older main-window service](https://github.com/EdgeTX/edgetx/blob/2273bda7b9e650c96a39a6e7f1316b6ef8415dad/radio/src/gui/colorlcd/libui/mainwindow.cpp#L57-L76), [older widget service](https://github.com/EdgeTX/edgetx/blob/2273bda7b9e650c96a39a6e7f1316b6ef8415dad/radio/src/lua/lua_widget.cpp#L294-L342), [modal layer](https://github.com/EdgeTX/edgetx/blob/2273bda7b9e650c96a39a6e7f1316b6ef8415dad/radio/src/gui/colorlcd/libui/modal_window.cpp#L52-L59).

**Standalone tools:** the 2.12.4 standalone Lua window explicitly disables widget refresh and pauses function/mixer Lua scripts. A separate Tools-menu diagnostics script would also have its own Lua state, complicating access to the owning widget's live state. Keep this feature inside KSE. [Standalone lifecycle](https://github.com/EdgeTX/edgetx/blob/def35ad324896b45d6607d4778536b1bc5360d20/radio/src/gui/colorlcd/standalone_lua.cpp#L128-L170).

Model changes, duplicate widgets, widget recreation, and fullscreen/layout changes still require KSE's ownership cleanup. There is no Lua widget deletion callback in the [native destructor](https://github.com/EdgeTX/edgetx/blob/def35ad324896b45d6607d4778536b1bc5360d20/radio/src/lua/lua_widget.cpp#L267-L272). Never retain a panel callback capable of reviving a retired owner or modifying another model's state.

## What the panel can honestly establish

| Evidence | Supported diagnostic statement | Limit |
| --- | --- | --- |
| `getFieldInfo(name)` | Whether the expected source resolves, plus its source ID/unit | Does not establish current reception. A renamed sensor can look missing. Duplicate names resolve to the first available matching slot; they are not unique identity. |
| `model.getSensor(index)` | Configured sensor label, unit, precision, type and custom ID/instance or calculated formula | Zero-based sensor-slot index is distinct from source ID. In-range empty slots return a table too; `nil` means out of range, not the only way a slot is empty. No last-packet time, error reason, or discovery control is returned. |
| `getValue(source)` | A display value | Zero is ambiguous: a valid measurement, missing source, disconnection, or restricted source can produce it. It cannot establish healthy telemetry. |
| `getSourceValue(source)` | Value with current/fresh flags; unavailable values can be nil and old values can remain accessible | Fresh is a short update pulse, not a packet sequence or exact timestamp. Current is not proof of recent-enough ARM for KSE. Retain independent live-link checks and the existing bounded ARM observation contract. |
| `model.getTimer(0)` | Timer 1 configuration, start and current value | It exposes neither a reset generation nor proof of flight duration/airborne state. |
| `getVersion()` | EdgeTX version numbers, radio identifier and OS name | Does not identify the FC firmware or installed RF Tool package. Probe required functions too; do not infer every capability from a version string. |
| Existing KSE/RF state | Provider missing/initializing, Auto identity waiting/confirmed, profile availability and current operation reason | Provider initialization state is not proof of why an RF link or FC failed. Do not add an MSP request merely to populate an explanation. |
| Existing counter/storage results | Last operation succeeded/failed, pending unsaved state, known parse/recovery state | File existence is not proof that the SD card is writable or healthy. Report an observed failure; do not invent a filesystem-wide health diagnosis. |

API evidence: [field resolution and first-match behavior](https://github.com/EdgeTX/edgetx/blob/def35ad324896b45d6607d4778536b1bc5360d20/radio/src/lua/api_general.cpp#L508-L531), [field metadata](https://github.com/EdgeTX/edgetx/blob/def35ad324896b45d6607d4778536b1bc5360d20/radio/src/lua/api_general.cpp#L634-L656), [sensor configuration](https://github.com/EdgeTX/edgetx/blob/def35ad324896b45d6607d4778536b1bc5360d20/radio/src/lua/api_model.cpp#L1746-L1771), [legacy value behavior](https://github.com/EdgeTX/edgetx/blob/def35ad324896b45d6607d4778536b1bc5360d20/radio/src/lua/api_general.cpp#L309-L321), [source values and flags](https://github.com/EdgeTX/edgetx/blob/def35ad324896b45d6607d4778536b1bc5360d20/radio/src/lua/api_general.cpp#L777-L859), [fresh implementation](https://github.com/EdgeTX/edgetx/blob/def35ad324896b45d6607d4778536b1bc5360d20/radio/src/telemetry/telemetry_sensors.h#L97-L128), [timer fields](https://github.com/EdgeTX/edgetx/blob/def35ad324896b45d6607d4778536b1bc5360d20/radio/src/lua/api_model.cpp#L305-L328), [version fields](https://github.com/EdgeTX/edgetx/blob/def35ad324896b45d6607d4778536b1bc5360d20/radio/src/lua/api_general.cpp#L176-L185). These functions were also present in the checked older pins. KSE state meaning remains governed by [compatibility](compatibility.md), including the four-second observed-fresh ARM window.

No supported API identified in the examined implementation can automatically open a particular native Telemetry setup tab, start sensor discovery, verify physical helicopter safety, or comprehensively audit an SD card. Give specific manual next steps where evidence supports them. Use separate `Missing`, `Waiting`, `Stale`, `Unavailable`, and `Not used in this mode` states rather than a single green/red installation verdict. A stored sensor and an observed update are separate facts.

## Resource and compatibility budget

There is no need for a new persisted option to open this panel. Preserve the original ten option slots; 2.11.5 has a ten-option ceiling, while 2.12.1/2.12.4 have 50. Existing KSE's version-gated slot 11 remains unchanged. [Older limit](https://github.com/EdgeTX/edgetx/blob/2273bda7b9e650c96a39a6e7f1316b6ef8415dad/radio/src/gui/colorlcd/mainview/widgets_container.h#L28), [current limit](https://github.com/EdgeTX/edgetx/blob/def35ad324896b45d6607d4778536b1bc5360d20/radio/src/gui/colorlcd/mainview/datastructs_screen.h#L92).

The checked current widget hook still uses a nominal 20,000 Lua instructions per invocation. DEBUG builds bypass the enforcement error. Opening/building, changed-state calculation, sensor enumeration and invoked RF service all need to fit their actual callbacks; break bounded inventory work over refreshes if needed. Retained label getters run after refresh and count toward foreground work. [Current hook](https://github.com/EdgeTX/edgetx/blob/def35ad324896b45d6607d4778536b1bc5360d20/radio/src/lua/widgets.cpp#L37-L99), [foreground property calls](https://github.com/EdgeTX/edgetx/blob/def35ad324896b45d6607d4778536b1bc5360d20/radio/src/lua/lua_widget.cpp#L294-L318).

`getUsage()` for LVGL widgets returns the stored completed foreground percentage; it is not a current-callback profiler or proof of background/create compliance. `getAvailableMemory()` reports underlying heap availability and its simulator result is a constant 1000. `collectgarbage("count")` measures the shared Lua state's managed heap, not native LVGL/images or a per-widget allocation. [Usage/memory API](https://github.com/EdgeTX/edgetx/blob/def35ad324896b45d6607d4778536b1bc5360d20/radio/src/lua/api_general.cpp#L2203-L2229), [simulator limitation](https://github.com/EdgeTX/edgetx/blob/def35ad324896b45d6607d4778536b1bc5360d20/radio/src/edgetx.cpp#L1978-L1995).

The current memory guard combines script/widget heaps and tracked extra memory. A 6 MiB limit on the examined Horus and rm-h750 targets is shared, not an individual dashboard allowance. Retaining two view roots trades fewer rebuilds for additional retained native objects: measure both choices if the smallest supported radio lacks margin. [Combined memory](https://github.com/EdgeTX/edgetx/blob/def35ad324896b45d6607d4778536b1bc5360d20/radio/src/lua/interface.cpp#L1310-L1331), [Horus](https://github.com/EdgeTX/edgetx/blob/def35ad324896b45d6607d4778536b1bc5360d20/radio/src/targets/horus/board.h#L59-L61), [rm-h750](https://github.com/EdgeTX/edgetx/blob/def35ad324896b45d6607d4778536b1bc5360d20/radio/src/boards/rm-h750/board.h#L43-L45).

Retain the project's every-prototype compiler gates (180 active locals / 230 registers) and its target below 75% of nominal callback budget. See [runtime resources](runtime-resources.md). Use fixed row counts and bounded state; no unbounded event history, repeated image loads, full-table clones per frame, or production-frame forced collections.

## Implementation gates

1. Prove the native entrypoint/focus flow in a small retained in-widget prototype on 2.11.5 and current 2.12.4: normal widget, fullscreen, app mode, touch and wheel/ENTER/EXIT. Verify that hidden dashboard controls leave the focus path and that fullscreen exit restores the dashboard.
2. Exercise all three resolutions with readable rows, no clipping, visible selected focus, usable touch targets, and an explicit way back. Check native focus/scroll and modal dismissal separately; Lua geometry mocks do not simulate them.
3. While diagnostics is open, verify continued normal telemetry, counters, Smart Fuel, alerts and RF Tool service; verify engine callbacks keep running on 2.11.5. Test standalone-tool pause/recovery without claiming continuous widget service there.
4. Test missing, renamed, duplicate, never-received, stale and returning sensors; missing `getSourceValue`; disconnected and initializing RF provider; Auto pending/changed identity; expired ARM evidence; unavailable optional instruments; storage failure/recovery. Read-only diagnostics must remain accessible in each case.
5. Confirm opening/closing/changing pages adds no MSP requests, changes no model settings, starts no sensor discovery and leaves active/foreign RF transactions alone. Snapshot construction must not call a mutating admission helper solely to explain a status.
6. Test repeated open/close, theme/layout changes, model switches and old callbacks. Record whole-callback instruction/time peaks, native/free-memory and shared Lua deltas on the smallest supported radio with normal enforcement; run KSE's assembly, compiler, ownership, RF-admission and render/behavior suites for both outputs.

Source review establishes feasibility and the limits above. It does not establish physical focus order, touchscreen precision, real-radio scheduling, memory headroom, or RF timing.
